# Trick or Treat Collection

noteで活動する参加者が、自分のキャラクターを使ったお菓子屋さんを開き、
ほかのお店を巡ってお菓子を集めるハロウィン企画サイトです。

## 企画の基本体験

1. note IDを入力して参加する
2. 自分のお店に、各自のAIで作ったキャラクター画像とお菓子画像を登録する
3. `https://<site>/shop/<note-id>` の専用URLを共有する
4. 訪問者が「トリック・オア・トリート！」を押す
5. その店に登録されたお菓子から1つがランダムで当たる
6. 初めて入手したお菓子が自分の図鑑に保存される
7. 異なる10店舗のお菓子を集めると、王子が登録した特別画像が解放される

抽選回数に制限は設けません。同じお菓子が重複して出ても、図鑑では1種類として記録します。

## アカウント方針

メールアドレスやパスワードは収集しません。公開上の識別子にはnote IDを使います。

ただし、note IDだけでは第三者が同じIDを入力してなりすませるため、初回登録時にブラウザ内で秘密鍵を生成します。通常利用では利用者に秘密鍵を意識させず、自動ログインとして扱います。

- 公開ID: note ID
- 認証情報: ブラウザで生成して端末に保存する秘密鍵
- 復旧手段: 初回だけ表示する引き継ぎコード
- 出店公開: 王子の管理画面から承認

詳細は [docs/identity-and-collection.md](docs/identity-and-collection.md) を参照してください。

## 画面

- `お店をひらく`: 店名、キャラクター、お菓子を登録して出店申請
- `お店をめぐる`: 公開店を選び、何度でも抽選
- `図鑑`: 入手したお菓子、重複数、10店舗までの進捗、特別画像
- `管理`: 出店承認と特別画像の登録（`/#/admin`）

メイン操作は画面下の3メニューへ集約しています。同じ参加IDで出店側と訪問側の両方を利用できます。

## 技術構成

- フロントエンド: モバイルファーストのWebアプリ
- API: Cloudflare Workers
- データベース: Cloudflare D1
- 画像保存: Cloudflare Workers KV（無料枠）
- 配信: Cloudflare Workers / Pages

画像生成APIは使用しません。お菓子画像は参加者が各自のAIで作成し、完成画像をアップロードします。

## ローカル起動

```bash
npm install
npm run db:migrate:local
npm run dev
```

構文確認と一連のAPIテスト:

```bash
npm run check
npm test
```

## Cloudflareへ公開

1. Cloudflareへログインします。

```bash
npx wrangler login
```

2. 管理者キーを登録します。

```bash
npx wrangler secret put ADMIN_TOKEN
```

3. 公開します。D1とKVは初回デプロイ時に自動作成され、テーブルは最初のAPIアクセス時に初期化されます。

```bash
npm run deploy
```

CloudflareのGit連携でも、D1とKVは自動作成されます。公開後にWorkerの設定から `ADMIN_TOKEN` をSecretとして登録してください。

## 実装済み

- note IDと端末秘密鍵による参加・自動ログイン
- 引き継ぎコードによる別端末への移行
- 店舗、キャラクター画像、お菓子画像の登録
- 管理者による出店承認
- 店舗ごとの共有URLとランダム抽選
- お菓子図鑑、重複回数、異なる店舗数の集計
- 10店舗達成時の特別画像解放
