# Trick or Treat Collection

noteで活動する参加者が、自分のキャラクターを使ったお菓子屋さんを開き、
ほかのお店を巡ってお菓子を集めるハロウィン企画サイトです。

## 企画の基本体験

1. note IDを入力して参加する
2. 自分のお店に、各自のAIで作ったキャラクター画像とお菓子画像を登録する
3. `https://<site>/#/shop/<note-id>` の専用URLを共有する
4. 訪問者が「トリック・オア・トリート！」を押す
5. その店に登録されたお菓子から1つがランダムで当たる
6. 初めて入手したお菓子が自分の図鑑に保存される
7. 異なる10店舗のお菓子を集めると、王子が登録した特別画像が解放される

抽選回数に制限は設けません。同じお菓子が重複して出ても、図鑑では1種類として記録します。

## アカウント方針

メールアドレスやパスワードは収集しません。公開上の識別子にはnote IDを使います。訪問・抽選・図鑑は、ブラウザが変わってもnote IDだけで利用できます。

この企画では手軽さを優先し、参加者の本人確認は行いません。note IDを入力すれば、どのブラウザからでも同じ参加データと店舗編集画面へ入れます。note IDは公開情報のため、なりすましを完全には防げない前提の運用です。

- 参加ID: note IDのみ
- 訪問・図鑑: note IDのみ
- 店舗作成・編集: note IDのみ
- 引き継ぎコード: 使用しない
- 管理画面: Cloudflare Secretの `ADMIN_TOKEN` を王子専用パスワードとして使用
- 出店公開: 必要な画像を登録して「出店する」を押すと即時公開

詳細は [docs/identity-and-collection.md](docs/identity-and-collection.md) を参照してください。

## 画面

- `お店をひらく`: 店名、キャラクター、お菓子を登録してそのまま出店
- `図鑑`: 訪れたお店、入手したお菓子、重複数、10店舗までの進捗、特別画像
- `管理`: 全店舗の確認・公開停止・削除、特別画像の登録（`/#/admin`）

メイン操作は画面下の「お店をひらく」「図鑑」の2メニューへ集約しています。公開店舗の全体一覧は表示せず、参加者から届いた専用URLを開いて訪問します。一度お菓子を受け取ったお店だけが図鑑の「訪れたお店」に追加されます。
管理画面の入口は「お店をひらく」画面の最下部にだけ表示します。

## 技術構成

- フロントエンド: モバイルファーストのWebアプリ
- API: Cloudflare Workers
- データベース: Cloudflare D1
- 画像保存: Cloudflare Workers KV（無料枠）
- 配信: Cloudflare Workers / Pages

画像生成APIは使用しません。お菓子画像は参加者が各自のAIで作成し、完成画像をアップロードします。

## ローカル起動

```bash
npm install
npm run db:migrate:local
npm run dev
```

構文確認と一連のAPIテスト:

```bash
npm run check
npm test
```

## Cloudflareへ公開

1. Cloudflareへログインします。

```bash
npx wrangler login
```

2. 管理者キーを登録します。

```bash
npx wrangler secret put ADMIN_TOKEN
```

3. 公開します。D1とKVは初回デプロイ時に自動作成され、テーブルは最初のAPIアクセス時に初期化されます。

```bash
npm run deploy
```

CloudflareのGit連携でも、D1とKVは自動作成されます。公開後にWorkerの設定から `ADMIN_TOKEN` をSecretとして登録してください。

## 実装済み

- note IDだけによる参加・自動ログイン
- 別ブラウザでも同じnote IDだけで利用・店舗編集
- 店舗、キャラクター画像、お菓子画像の登録
- キャラクター画像は横4:3、お菓子画像は正方形1:1の推奨比率を画面に表示
- 店舗説明の改行を公開画面へ反映
- 承認なしの即時出店と、管理者による全店舗確認・公開停止・削除
- 店舗ごとの共有URLとランダム抽選
- お菓子図鑑、重複回数、異なる店舗数の集計
- 10店舗達成時の特別画像解放
