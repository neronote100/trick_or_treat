# ハロハロおかしラリー / Trick or Treat Collection

noteで活動する参加者が、自分のキャラクターを使ったお菓子屋さんを開き、
ほかのお店を巡ってお菓子を集めるハロウィン企画サイトです。

## サイトのタイトルとトップ画像

サイト名・ブラウザタイトル・note等のOGP表示は「ハロハロおかしラリー」に統一しています。トップのキービジュアルは `public/halo-oka-rally-banner.webp`（1536×804、横長・文字入り）。初めての訪問者は画像とイベント案内を見た後、note IDを登録して図鑑やお店作成を利用できます。既存のnote ID・ガチャ・図鑑データは変更しません。

## 企画の基本体験

1. note IDを入力して参加する
2. 自分のお店に、各自のAIで作ったキャラクター画像とお菓子画像を登録する
3. `https://<site>/shop/<note-id>` の専用URLを共有する
4. 訪問者が「トリック・オア・トリート！」を押す
5. その店に登録されたお菓子から1つがランダムで当たる
6. 初めて入手したお菓子が自分の図鑑に保存される
7. 異なる10・20・30店舗でゲートを突破し、続いて現れる隠しステージ（50・75・100店舗）へ進む
8. 各ゲートで、王子が登録した特別画像を解放する（最終目標は100店舗）

抽選回数に制限は設けません。同じお菓子が重複して出ても、図鑑では1種類として記録します。
ゲートは異なる店舗数で判定します。100店舗は報酬の最終目標であり、達成後もほかの店舗の訪問や抽選は可能です。

## お店別コンプリートマーク

- 図鑑の「訪れたお店」に限り、登録された全ての公開中（有効）のお菓子を1種類ずつ入手すると、カードに金色の「✦ コンプリート！」マークを付けます。
- 未達成の店に総種類数・残り種類数を表示しません。お店のガチャ画面の「？」は固定3個の飾りで、種類数を表しません。公開のお店取得APIにも総種類数を返しません。
- 達成後に店主が新しいお菓子を追加してもマークは保持します。お店そのものが削除された場合は達成履歴も消えます。
- 導入前に既に全種類を集めていた参加者は、次に図鑑を開いたときに自動的に達成判定を行います。
- データは `shop_completions` に保存。初回APIリクエスト時の自動テーブル作成と `migrations/0003_shop_completions.sql` に対応しています。

## 3枚合体イラスト（10・20・30店舗）

管理画面の「3枚合体イラスト（3:1）」へ**横3:縦1の画像を1枚**登録するだけで、ブラウザが左・中央・右の1:1画像を自動生成して一緒に保存します。手作業の分割は不要です。

図鑑の表示位置と解放順は意図的に異なります。

| 到達店舗数 | 解放する欠片 | 図鑑での位置 |
| --- | --- | --- |
| 10 | 左 | 左 |
| 20 | 右 | 右 |
| 30 | 中央 | 中央 |

図鑑の並び順は **10（左）・30（中央）・20（右）** です。30店舗達成で完成した**3:1画像**を図鑑の専用枠に表示します。

- 完成画像は3:1比率（例：3600×1200px）、PNG / JPEG / WebP / GIF、ファイルサイズ5MB以下
- 1回のアップロードから完成画像＋3パネルを保存し、到達前のパネル画像や完成画像のURLはAPIで渡しません
- 管理者が画像を差し替えると、達成済みの参加者も図鑑を開くだけで新しい画像が表示されます
- 画像が未登録でも10・20・30店舗の達成記録は保存され、あとから登録可能です
- **10・20・30店舗のゲート報酬と3:1画像は自動同期します**。10=左、20=右、30=中央。ゲート画像を別途アップロードする必要はありません
- 以前に3:1画像を登録していても、管理画面の再表示または図鑑の表示時にゲート報酬枠を自動修復します。再アップロードは不要です
- 3:1登録後は10・20・30店舗の手動差し替えを禁止し、画像の食い違いを防ぎます。50・75・100店舗の独立報酬は従来どおり管理できます
- 古い個別報酬はDB内に保持して非表示にし、同期後の3枚を現行のゲート報酬にします
- 既存のCloudflare D1には `triptych_illustrations` テーブルを自動追加します。SQLマイグレーションも `migrations/0002_triptych_illustration.sql` に用意しています

## アカウント方針

メールアドレスやパスワードは収集しません。公開上の識別子にはnote IDを使います。訪問・抽選・図鑑は、ブラウザが変わってもnote IDだけで利用できます。

この企画では手軽さを優先し、参加者の本人確認は行いません。note IDを入力すれば、どのブラウザからでも同じ参加データと店舗編集画面へ入れます。note IDは公開情報のため、なりすましを完全には防げない前提の運用です。

- 参加ID: note IDのみ
- 訪問・図鑑: note IDのみ
- 店舗作成・編集: note IDのみ
- 引き継ぎコード: 使用しない
- 管理画面: Cloudflare Secretの `ADMIN_TOKEN` を王子専用パスワードとして使用
- 出店公開: 必要な画像を登録して「出店する」を押すと即時公開

詳細は [docs/identity-and-collection.md](docs/identity-and-collection.md) を参照してください。

## 管理者向け参加者一覧（お菓子収集状況）

`/#/admin` で管理者パスワードを入力すると、画面の上部に **「🍬 参加者・お菓子収集状況」** が表示されます。登録されたnote IDすべて（未出店・未収集を含む）を表示します。

- **訪問店舗**：図鑑に残っている異なる出店者の店舗数
- **お菓子の種類**：図鑑に残っている異なるお菓子数
- **取得回数**：図鑑に残っているお菓子の取得回数合計（重複ガチャを含む）
- 登録日、本人の出店状態、達成ゲート、noteプロフィールへのリンクも表示
- デフォルトは訪問店舗数が多い順。note ID検索（部分一致）、**25 ID／ページ**でページ切り替え
- 登録ID数・収集開始ID数の全体件数を表示。検索した場合は検索に一致する件数も表示
- `GET /api/admin/participants?page=1&q=... ` は `x-admin-token` の管理者認証が必要で、未認証では401
- 参加者情報は現在の図鑑に残る記録が対象。お店・お菓子が削除されると集計値も減少します
- 登録IDは本人確認をしていないため「実在する本人の数」ではありません
- 新しいテーブルやマイグレーションは不要。既存の `users`、`collection_items`、`treats`、`shops` を参照します

## 画面

- `お店をひらく`: 店名、キャラクター、お菓子を登録してそのまま出店
- `図鑑`: 訪れたお店、入手したお菓子、重複数、100店舗までのゲート進捗、特別画像
- `管理`: 全店舗の確認・公開停止・削除、ゲート別特別画像の登録・差し替え（`/#/admin`）

メイン操作は画面下の「お店をひらく」「図鑑」の2メニューへ集約しています。公開店舗の全体一覧は表示せず、参加者から届いた専用URLを開いて訪問します。一度お菓子を受け取ったお店だけが図鑑の「訪れたお店」に追加されます。
管理画面の入口は「お店をひらく」画面の最下部にだけ表示します。

## 技術構成

- フロントエンド: モバイルファーストのWebアプリ
- API: Cloudflare Workers
- データベース: Cloudflare D1
- 画像保存: Cloudflare Workers KV（無料枠）
- 配信: Cloudflare Workers / Pages

画像生成APIは使用しません。お菓子画像は参加者が各自のAIで作成し、完成画像をアップロードします。

## ローカル起動

```bash
npm install
npm run db:migrate:local
npm run dev
```

構文確認と一連のAPIテスト:

```bash
npm run check
npm test
```

## Cloudflareへ公開

1. Cloudflareへログインします。

```bash
npx wrangler login
```

2. 管理者キーを登録します。

```bash
npx wrangler secret put ADMIN_TOKEN
```

3. 公開します。D1とKVは初回デプロイ時に自動作成され、テーブルは最初のAPIアクセス時に初期化されます。

```bash
npm run deploy
```

CloudflareのGit連携でも、D1とKVは自動作成されます。公開後にWorkerの設定から `ADMIN_TOKEN` をSecretとして登録してください。

## 実装済み

- note IDだけによる参加・自動ログイン
- 別ブラウザでも同じnote IDだけで利用・店舗編集
- 店舗、キャラクター画像、お菓子画像の登録
- キャラクター画像は横4:3、お菓子画像は正方形1:1の推奨比率を画面に表示
- 店舗説明の改行を公開画面へ反映
- 承認なしの即時出店と、管理者による全店舗確認・公開停止・削除
- 店舗ごとの共有URLとランダム抽選
- 店舗共有URLごとに店名・紹介文・登録キャラクター画像をOGPへ反映
- お菓子図鑑、重複回数、異なる店舗数の集計
- 10・20・30・50・75・100店舗での段階的なゲート解放（後半は隠しステージ）
- ゲート別特別画像の登録と解放、達成後の画像追加にも対応
