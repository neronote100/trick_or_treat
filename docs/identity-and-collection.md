# ID認証・出店・図鑑の設計

## 1. 目的

メールアドレスやパスワードを求めず、note IDだけで気軽に参加できる体験を維持しながら、次の状態をサーバーへ保存します。

- 自分のお店と登録した画像
- 訪問した店舗
- 入手したお菓子
- 10店舗達成状況
- 特別画像の解放状況

## 2. IDだけを認証情報にしない

note IDは誰でも確認できる公開情報です。そのため、note IDだけを認証情報として扱うと、第三者が次の操作を行えます。

- 他人の店舗を編集する
- 他人名義で出店する
- 他人の図鑑を上書きする

訪問・抽選・図鑑にはnote IDを使います。店舗の作成・編集・削除権限の確認には、端末で生成した秘密鍵を使います。別のブラウザで同じnote IDを入力しても図鑑は利用できますが、店舗は編集できません。

## 3. 初回参加フロー

1. 利用者がnote IDを入力する
2. 未登録IDなら、ブラウザが十分に長いランダムな店舗編集用秘密鍵を生成する
3. ブラウザは秘密鍵を端末内に保存する
4. サーバーには秘密鍵そのものではなく、検証用のハッシュ値を保存する
5. サーバーが復旧用の引き継ぎコードを発行する
6. 利用者に引き継ぎコードを一度だけ表示し、スクリーンショット保存を案内する
7. 登録済みIDなら、秘密鍵を要求せず訪問モードで開始する
8. 店舗編集は秘密鍵を持つブラウザ、または引き継ぎ後のブラウザだけに許可する

利用者から見える入力項目はnote IDだけです。通常は次回アクセス時に端末内の秘密鍵を使って自動ログインします。

## 4. 引き継ぎ

スマートフォンの変更やブラウザデータの削除に備え、引き継ぎコードを用意します。

- 別端末では `note ID + 引き継ぎコード` を入力する
- 照合成功後、新しい端末用の秘密鍵を生成する
- 使用済みの引き継ぎコードは無効化し、新しいコードを表示する
- コードは推測しにくい十分な長さにする

引き継ぎコードを紛失した場合、メールによる自動復旧は行いません。管理者が本人確認後、管理画面で新しい引き継ぎコードを発行します。再発行すると以前のコードは無効になります。

## 5. 出店フロー

1. 利用者がキャラクター画像、店名、紹介文を登録する
2. お菓子画像を1枚以上登録する
3. 「出店する」を押すと店舗状態を `published` にする
4. 店舗URLをすぐ公開する
5. 王子は管理画面ですべてのお店を確認し、必要な場合だけ公開停止する

店舗URLの形式:

```text
/#/shop/<note-id>
```

例:

```text
/#/shop/nero_notelover
```

note IDには英数字とアンダースコアのみを許可し、URLでは小文字へ正規化します。

## 6. 店舗訪問と抽選

1. 店主から共有された専用URLで公開店舗を開く
2. 「トリック・オア・トリート！」を押す
3. サーバーが公開中のお菓子からランダムに1つ選ぶ
4. 抽選結果を表示する
5. 初入手なら図鑑へ追加する
6. 重複なら入手回数だけ増やす

公開店舗の全体一覧は表示しません。一度お菓子を受け取った店舗だけを、図鑑の「訪れたお店」に追加します。

抽選回数は制限しません。初版ではボタン処理中の再操作を画面側で止めます。公開規模が大きくなった場合は、サーバー側にも短時間の連続リクエスト制限を追加します。

## 7. 図鑑

図鑑では次を表示します。

- 入手済みのお菓子画像
- お菓子名
- 店舗名と店主のnote ID
- 初回入手日時
- 入手回数
- 店舗内の未発見枠
- 異なる店舗の訪問達成数 `n / 10`

異なる10店舗から1種類以上のお菓子を入手した時点で、特別報酬を解放します。同じ店舗で何度引いても、店舗達成数は1として数えます。

## 8. 特別報酬

- 王子が管理画面から特別画像を事前登録する
- 達成判定はサーバー側で行う
- 条件達成後は図鑑に特別枠を表示する
- 一度解放した報酬は、店舗数が後から変動しても原則として保持する

初版の条件:

```text
異なる公開店舗10店から、お菓子を1種類以上入手する
```

## 9. 最小データモデル

### users

| 列 | 用途 |
|---|---|
| id | 内部ユーザーID |
| note_id | 公開ID・一意 |
| credential_hash | 端末秘密鍵の検証用ハッシュ |
| recovery_code_hash | 引き継ぎコードの検証用ハッシュ |
| created_at | 登録日時 |

### shops

| 列 | 用途 |
|---|---|
| id | 店舗ID |
| owner_user_id | 店主 |
| name | 店名 |
| description | 紹介文 |
| character_image_key | キャラクター画像のKVキー |
| status | draft / pending / published / suspended |

### treats

| 列 | 用途 |
|---|---|
| id | お菓子ID |
| shop_id | 所属店舗 |
| name | お菓子名 |
| image_key | お菓子画像のKVキー |
| rarity | 通常 / レア / シークレット |
| weight | 抽選重み |
| is_active | 抽選対象か |

### collection_items

| 列 | 用途 |
|---|---|
| user_id | 取得者 |
| treat_id | お菓子 |
| first_obtained_at | 初回入手日時 |
| obtained_count | 入手回数 |

`user_id + treat_id` に一意制約を設定します。

### rewards

| 列 | 用途 |
|---|---|
| id | 報酬ID |
| required_shop_count | 必要店舗数 |
| image_key | 特別画像のKVキー |
| is_active | 現在の報酬か |

### user_rewards

| 列 | 用途 |
|---|---|
| user_id | 達成者 |
| reward_id | 報酬 |
| unlocked_at | 解放日時 |

## 10. セキュリティ上の約束

- 秘密鍵と引き継ぎコードの平文をデータベースに保存しない
- 店舗編集APIは秘密鍵の照合を必須にする
- note IDだけでは店舗を編集できない
- 画像はファイル形式、容量、縦横サイズを検査する
- SVGは初版では受け付けない
- 準備中・公開停止中の店舗を一覧や抽選へ表示しない
- 管理画面は一般利用者とは別の管理者認証で保護する
- 抽選と報酬解放の判定はブラウザではなくサーバー側で行う

## 11. 初版の割り切り

- note本体のアカウントと連携したログインは行わない
- note IDの所有権確認は行わず、端末秘密鍵で同じIDの編集権限だけを保護する
- メールによる復旧は行わない
- 引き継ぎコード紛失時は管理者対応とする
- 1アカウントにつき1店舗とする

## 12. 完了条件

- note IDだけで初回参加できる
- 同じ端末では再入力なしで戻れる
- 他人が同じnote IDを入力しても店舗を編集できない
- 引き継ぎコードで別端末へ移行できる
- 必要な画像を登録すると承認なしで出店できる
- 管理者が全店舗を一覧で確認し、必要な店舗を公開停止できる
- 公開店で何度でも抽選できる
- 入手したお菓子が図鑑へ保存される
- 異なる10店舗で特別画像が解放される
