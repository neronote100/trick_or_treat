# ID認証・出店・図鑑の設計

## 1. 目的

Trick or Treat Collectionでは、メールアドレス・認証コード・引き継ぎコードを使わず、note IDだけで気軽に参加できる体験を優先します。

保存対象:

- 自分のお店と登録した画像
- 訪問した店舗
- 入手したお菓子
- 10・20・30・50・75・100店舗のゲート達成状況
- 特別画像の解放状況

## 2. 参加者認証

参加者はnote IDだけを入力します。

- 初回: note IDを入力するとユーザーを作成
- 既存ID: 同じnote IDを入力すると既存データを利用
- 同じブラウザ: localStorageにnote IDを保存して自動復帰
- 別ブラウザ・別端末: note IDを入力するだけで利用可能
- 店舗作成・編集・お菓子追加・削除もnote IDのみ

note IDは公開情報なので、この方式は本人確認ではありません。第三者が他人のnote IDを入力する可能性は残ります。この企画では期間限定イベントとして操作の簡単さを優先し、管理者が問題のある店舗を公開停止できる構成にします。

## 3. 管理者認証

管理画面は参加者認証とは分離します。

- 管理画面: `/#/admin`
- 認証方法: 王子だけが知っているパスワード
- 保存先: Cloudflare Secretの `ADMIN_TOKEN`
- メール認証コードは使用しない
- ワンタイムコードは使用しない

ブラウザから入力されたパスワードは `x-admin-token` としてWorkerへ送り、Cloudflare Secretの `ADMIN_TOKEN` と一致する場合だけ管理APIを許可します。

## 4. 出店フロー

1. 利用者がnote IDで参加する
2. キャラクター画像、店名、紹介文を登録する
3. お菓子画像を1枚以上登録する
4. 「出店する」を押す
5. 店舗状態を `published` にする
6. 店舗URLを共有する

店舗URL:

```text
/shop/<note-id>
```

共有URLはCloudflare Workerが動的HTMLを返し、公開中店舗の店名・紹介文・登録キャラクター画像をOGP（`og:title` / `og:description` / `og:image`）へ設定します。noteなどへURLを貼った際に店舗ごとのカードが表示される設計です。

## 5. 店舗訪問と抽選

1. 共有された店舗URLを開く
2. note ID未入力なら自分のnote IDを入力する
3. 「トリック・オア・トリート！」を押す
4. サーバーがお菓子を抽選する
5. 初入手なら図鑑へ追加、重複なら入手回数を加算する

## 6. 図鑑

図鑑では次を表示します。

- 入手済みのお菓子
- お菓子名
- 店舗名と店主note ID
- 入手回数
- 訪れた店舗
- 異なる店舗の達成数
- 解放済み特別画像

10・20・30店舗を突破するごとに次のゲートを表示します。30店舗以降は50・75・100店舗の隠しステージが順番に登場します。各店舗から1種類以上のお菓子を入手すると1店舗として数えます。

各ゲートの画像報酬は管理者が登録したときに解放されます。先に条件を満たした人も、後から報酬画像が登録された場合は図鑑を開くことで受け取れます。100店舗が最終ゲートですが、抽選・訪問そのものは制限しません。

### 3枚合体イラストの進行

管理画面から3:1画像を1枚登録すると、管理ブラウザで左・中央・右の3枚の正方形画像を生成し、一括でアップロードします。画像のアップロードは管理者パスワードが必要です。

- 10店舗：左の欠片だけ公開
- 20店舗：右の欠片を追加公開（中央はまだ鍵付き）
- 30店舗：中央の欠片を追加公開。3つそろった全体イラスト（3:1）を解放
- 図鑑の表示位置：左10／中央30／右20
- 10・20・30店舗の従来の個別報酬枠にも同じ画像を自動同期し、古い手動登録は非表示にします
- すでに3:1画像がある場合は管理画面・図鑑・抽選時に同期漏れを検知して修復します
- 3:1登録後の10・20・30店舗手動画像登録は不可。50・75・100店舗は通常どおり登録可能
- 画像差し替え時はD1で合体画像と3報酬枠をまとめて更新した後に古いKV画像を削除
- これまでの個別報酬・図鑑のデータは削除せず維持

専用テーブル `triptych_illustrations` は完成画像、3枚の欠片、作品名を保存します。図鑑APIは解放済みの画像URLのみ返し、管理画面APIのみ全画像を返します。登録済み画像の差し替え後は、すべての達成済み参加者に新しい画像が反映されます。

## 7. 管理

王子は管理画面から以下を行えます。

- 全店舗の確認
- 店舗の公開停止
- 停止店舗の再公開
- 店舗の完全削除
- 6段階のゲート別特別画像の登録・差し替え

公開停止した店舗は再公開するまで利用できません。完全削除した場合は店舗・登録お菓子・関連画像を削除し、同じnote IDで新しい店舗を一から作成できます。削除した店舗のお菓子は取得者の図鑑からも消えます。

参加者向けの引き継ぎコード再発行機能は廃止します。

## 8. データモデル

既存DBとの互換性維持のため、`users` テーブルの `credential_hash` と `recovery_code_hash` 列は当面残します。ただし新しい認証フローでは使用しません。

主要な識別子は以下です。

- `users.note_id`: 参加者の公開ID、一意
- `shops.owner_user_id`: 店舗所有者
- `collection_items.user_id`: 図鑑所有者

## 9. セキュリティ上の割り切り

- note IDの所有権確認は行わない
- note IDだけで店舗編集できる
- なりすましを完全には防げない
- 問題が起きた店舗は管理者が公開停止する
- 管理者パスワードはGitHubへ書かずCloudflare Secretで保持する
- 管理者APIは `ADMIN_TOKEN` が一致した場合だけ許可する
- 画像アップロードは形式と容量を検査する
- 抽選と報酬解放判定はサーバー側で行う

## 10. 完了条件

- note IDだけで初回参加できる
- 同じブラウザでは再入力なしで戻れる
- 別ブラウザでもnote IDだけで入れる
- note IDだけで自分の店舗を作成・編集できる
- 認証コードを要求しない
- 引き継ぎコードを要求しない
- 管理画面はCloudflareの既存 `ADMIN_TOKEN` パスワードで保護される
