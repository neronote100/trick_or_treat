# 🎄 クリスマスキングダム2026 — オーナメント＆サンタさんの贈り物

**noteに企画専用タグを付けて投稿するだけで、ツリーにオーナメントが灯る／サンタさんのツリーの根元にプレゼントが届く**静的Cloudflare Pagesサイト。URL入力、運営承認、参加回数制限なし。

## 参加の仕組み

1. 参加者はnoteで記事を公開し、**共通タグ** `#クリスマスキングダム2026` と、参加する**各ツリーの専用タグ**を付ける（専用タグが収集のキー）。
2. GitHub Actionsが**毎時13分・43分（目安）**に4タグの公開RSSを巡回。GitHubによるスケジュール遅延・noteの反映遅延は起きる。
3. note RSSから公開記事のURL・タイトル・作者・画像を取得し、`christmas-tree/data/ornaments.json` に**自動蓄積**。同一作品・同一企画は重複排除。複数作品も可。RSSから一時的に消えても過去に集めた作品は残す。
4. データが変化した場合だけGitHubにコミットされ、Cloudflare Pagesが別URLのクリスマスサイトを再デプロイ。**旧ハロウィンのソース・DBは変更しない**。
5. 通常3企画ではサムネイルが金縁オーナメントとなって表示され、タップするとnote記事へ。サンタ企画では**サムネイルを隠したプレゼント箱**としてツリーの下に届き、タップで箱を開封するとサムネイルとnoteへのリンクが現れる。
6. 通常3企画は**1本48オーナメント**、サンタ企画は**1本12プレゼント**まで。どちらも3本を超えたら「次の森」に切り替え。

## 🎅 サンタさん企画（2026-11-23復活・企画準備中）

- 専用 project id は santa、表示 mode は gifts、色テーマは santa-gifts。作品は通常のオーナメントとして枝に飾らず、**ツリーの根元に色とりどりのプレゼントとして表示する**。
- 記事1件につき箱1個。タグ収集器 scripts/collect.py は config.json の projects を自動走査するため、新規の収集器・データベースは不要。
- プレゼントはクリック／タップ／Enter・Spaceで開き、蓋が開いたままサムネイルが現れる。サムネイルのリンクからnote記事を開く。開封前は作品一覧にも記事のタイトル・画像を出さない。
- **開封状態をブラウザの localStorage に記事URL単位で保存**し、同じ端末とブラウザでは画面の再訪・データ更新後も開封状態を復元する。端末やブラウザが違う場合、プライベートモード、ストレージ削除時などは共有・維持されない。
- 追加記事は元の収集器が first_seen 昇順で保持し、新しい未開封の箱が後ろに増える。12件ごとにツリーを追加、3本ごとに森をページ分けする。
- プレゼントが未着なら空の雪原メッセージを出し、3Dツリーは通常どおり回転できる。贈り物用のツリーにはnoteの球体オーナメントを描画しない。
- カラーは深いモミの木のグリーン×クリスマスレッド×シャンパンゴールド。実際のThree.js樹冠とイルミネーションもサンタ用に色を切り替える。
- **専用タグ #キングダムサンタ2026 は過去に使っていた仮名称を復帰させたもの。主催者と確定するまでは募集を開始しない**（accepting:false）。タグが確定したら hashtag と accepting の告知内容を更新する。
- アーカイブ（王子ごっこなど548件）の archive_projects・archive.json、旧ハロウィンは変更なし。

## ハッシュタグの管理（**仮のタグ名。主催者と確定後にconfig.jsonで修正すること**）

| 企画 | 仮の専用タグ | 主催に関する表示 |
| --- | --- | --- |
| 届けないラブレター | `#キングダム恋文2026` | らてさん × 王子 |
| 好きの告白 | `#キングダム告白2026` | 企画準備中 |
| クリスマスカード | `#キングダムカード2026` | 企画準備中 |
| 全国のサンタさん | `#キングダムサンタ2026` | 企画準備中 |

**共通タグだけではどのツリーに飾るか判定できない。** 必ず専用タグも付けるよう告知。複数の専用タグを付けた記事は複数ツリーに飾られる。 `config.json` の `projects[].hashtag` と `common_hashtag` を編集するとサイトの案内・RSS対象をまとめて変更できる。`projects[].accepting` は「募集中／準備中」表示のためのスイッチであり、RSSの収集は止めない。未確定の企画では他人に仮タグでの参加を求めないこと。

### 収集上の制約
- noteの `https://note.com/hashtag/タグ名/rss` に依存。**タグ検索/フィードは公式の漏れのない応募APIではない**。noteの2026年検索仕様ではキーワードページになる場合があり、検索の反映にも遅延がある。タグRSSが一時的に失敗しても前回データは消さない。
- **反映は即時ではない**。GitHub ActionsのスケジュールやCloudflareのビルドにも遅延がある。
- 新しいタグでまだ記事がない間はRSSが404等で失敗する場合がある。警告を出して次回再試行する。
- 過去記事に後からタグを付けてもRSSの最新記事範囲に入らないことがある。どうしても取得できない記事は、管理者が `manual_articles` に `project_id,url,title,author,thumbnail` を追加可能（手動確認・承認を必須にする仕組みではない）。
- 新しく見つかった記事は**自動公開**。不適切な作品や掲載取り下げは `exclude_urls`（全ツリー）または `exclude_by_project: [{"project_id":"letter","url":"https://note.com/.../n/n..."}]`（該当ツリーのみ）で自動掲載対象から外せる。通常のタグ除去だけでは蓄積済みの作品は消えないため注意。
- 記事の画像URLは元のnoteの画像にリンクし、取得できない場合は代替表示。本文の転載は行わない。
- `max_articles` の初期値1000、最大3000件。あくまでサーバー側スクリプトの実装上の保持件数でありRSSの完全性を意味しない。

## Cloudflareの設定

すでに公開中の **`christmas-kingdom-2026.pages.dev`** を引き続き使用。GitHub `main` の `christmas-tree/` だけをPagesとしてビルド。

- Root directory: `christmas-tree`
- Framework: None
- Build command: `npm run build`
- Build output: `dist`

`scripts/build.mjs` は `data/ornaments.json` も `dist/data/` にコピーする。**公開ページはD1やCloudflare Functionsをもう使用しない**。以前に作成したD1/Secretは削除せず残しても表示に影響はしないが、今のサイトの自動収集には不要。管理画面 `admin.html` と登録APIは廃止。

### ハロウィンサイトへの影響

クリスマスの記事収集で `main` にデータファイルのコミットが発生すると、**同じGitHubリポジトリを監視しているハロウィンWorkerも再ビルドされる可能性**がある。ハロウィンのソースは変化しないものの、不要なデプロイを避けるにはCloudflare Workers BuildsのBuild watch pathsで `christmas-tree/**` の変更を除外し、ハロウィンの対象のみを監視する設定を推奨。これを設定するまでは頻繁な自動更新でハロウィン側のビルド回数が増える可能性がある。

## 自動収集の実行・テスト

- GitHub Actions → **Christmas Kingdom - auto-publish tagged note articles** → Run workflow で手動試験可能（`main`）。
- 定期実行は毎時13分・43分（実際はGitHubの混雑で遅延あり）。
- 検証：`cd christmas-tree && npm test && npm run build && python3 -m unittest discover -s tests -v`
- 公開JSON： `https://christmas-kingdom-2026.pages.dev/data/ornaments.json`
- 投稿作品がまだ0件なら `articles: []` は正常。最新の処理状況はGitHub ActionsのログとJSONの `sources/warnings` を確認。

## 参加・掲載の告知に必ず記載すること

> 企画専用ハッシュタグを付けた公開記事は、運営による承認を挟まず、タイトル・作者名・見出し画像・記事へのリンクがクリスマスキングダムの外部公開サイトへ自動掲載されます。掲載まで時間差が生じたり、タグ付きでも取得漏れが起きることがあります。掲載取り下げをご希望の方は主催者へご連絡ください。

らてさんの恋愛交流フェスなど、**既存のイベント独自のタグを無条件に新サイトへ取り込むことは避ける**。主催者の了解を取り、クリスマスキングダム専用タグの追加を参加希望の意思表示とすることで、別企画へ勝手に掲載されないようにする。

クリスマス本番は **届けないラブレター / 好きの告白 / クリスマスカード** の3企画のみ。サンタ企画は対象外。

過去企画 #王子ごっこ / #秋読コレクション / #ハロハロウィーン の公開RSSを収集し、**クリスマス応募とは別の** `data/archive.json` に蓄積。`archive.html` で試験表示する。`data/ornaments.json` のクリスマス参加者には混ぜない。

## 2026-11-20 : 豪華ツリー素材と分散植樹

`assets/royal-tree.svg` は生成した幻想的な金色のツリーアート（GitHub管理のSVG、プログラムで生成）。各ツリーに15作品までオーナメントを飾り、16作品目から2本目、31作品目から3本目を自動で植樹します。1画面の表示は最大3本まで、以後は『次の森』で切り替えます。オーナメントと記事一覧のリンク先はnoteの元記事。


## 画像生成した高精細ツリーの登録

`assets/royal-tree.avif` は、クリスマスキングダムのためにAI画像生成した縦長のファンタジーツリー画像をWeb公開向けに最適化したファイル（768×1152px、約48KB）。表示時はこの画像を優先し、AVIF非対応環境や読み込み失敗時は `royal-tree.svg` に自動フォールバックします。外部画像ホストへの依存はありません。


## 2026-11-20：360度オーナメントリング

- 既存の豪華なツリー画像はそのまま使用。木本体の3Dモデル化ではなく、サムネイルを3段の円周上に投影する**疑似3D・360度回転**方式。
- **1本24作品**（上段5・中段8・下段11）。25作品目から2本目、49作品目から3本目。3本を超えると「次の森」。
- 自動回転は約3.6度/秒。左右ボタン・自動停止／再開・横スワイプ／ドラッグで操作。速度・加速度に連動したバネ・減衰で紐付きの飾りが自然に揺れる。
- 後ろ側の飾りは薄くしてクリックとTab移動を無効化。記事一覧では全作品を閲覧可能。
- キーボード操作、動きの軽減設定（prefers-reduced-motion）に対応。スマホ負荷を抑えるためオーナメント投影は約30fpsで更新。
- 本番3企画と過去3企画アーカイブの両方に同じデザインを適用。ハロウィンサイトのコードには変更なし。


## 2026-11-20 — 本物の3Dツリーへの改修（試作）

- 木は画像4枚の板を交差させた「疑似3D」ではなく、**Three.jsのWebGLによる実際の3Dメッシュ**（幹・8段の円錐状の樹冠・数百本の立体的な枝葉・立体の星・3D螺旋の金色リボン・イルミネーション）として描画。
- note記事のオーナメントは**1本48作品**（6/10/14/18の4段）。3D空間内の球体の位置をブラウザへ投影し、手前に来たサムネイルだけをクリック可能にする。裏側の装飾は3D空間に残り、自然に樹冠に遮られる。
- 木本体・枝葉・飾り・金色のガーランド・星を同じ3Dグループとして回す。物理的な揺れは従来の減衰バネで継続。
- Three.js r170をバージョン固定したHTTPS ESモジュールで読み込み（外部CDN）。WebGLやCDNが利用不可の場合は静止画を表示し、note記事一覧のリンクを維持する。
- スマホ向けにDPR最大1.45、インスタンス描画、30fps上限、非表示時更新停止、ページ切替時GPUリソース破棄を実施。
